# 杭州·低空智航实验室

一个以杭州城市低空应用为题材的纯前端无人机小游戏合集。玩家从低空任务中枢进入 8 个任务模块，每个模块有 3 个递进关卡；项目沿用原项目的 TypeScript + Vite、Canvas 2D、屏幕栈、事件驱动 HUD 和深色航天控制台视觉架构。

地图和任务场景是教学用示意，不使用实时 GIS、真实空域或真实无人机遥测数据。航线建议、任务分配和 AI 告警复核均在浏览器本地运行，用可解释的启发式规则演示决策权衡；项目不调用云端 AI 服务，也不提供真实飞行指令。

## 启动与构建

需要 Node.js 和 npm。

```bash
npm install
npm run dev
```

Vite 默认在 `http://localhost:5173` 提供开发版。常用检查和预览命令：

```bash
npm run typecheck
npm run build
npm run preview
```

`build` 会先运行 TypeScript 检查，再生成 Vite 生产构建到 `dist/`。

## 八个无人机任务

| 编号 | 项目与核心操作 | 玩家要做的独立判断 | 轻科普主题 |
| --- | --- | --- | --- |
| 01 | 风廊急送：操控无人机连续投递急救包 | 借风穿街、提前刹车，并在落点圈内低速投放 | 飞行惯性、侧风修正、地速与精准投递 |
| 02 | 杭州航线编程：编排方向/步数积木后运行 | 调试程序次序、避开楼宇并通过检查点 | 网格路径规划与安全约束 |
| 03 | 城市航测拼图：拖动、旋转航摄影像 | 从道路、河岸和建筑纹理判断地块邻接关系 | 影像重叠、摄影测量与覆盖检查 |
| 04 | AI 巡检鉴证：标记证据并复核告警 | 对照可见光/热成像，区分缺陷与误报 | AI 置信度、传感器证据与人工复核 |
| 05 | 汛情绞车救援：调节绳长并选择接救时机 | 观察吊具摆幅、目标漂移和相对速度 | 摆动惯性、风扰与安全交接窗口 |
| 06 | 通信组网：移动并升高中继无人机 | 绕过建筑遮挡，用有限节点建立端到端连通 | 视距链路、覆盖与网络冗余 |
| 07 | 货舱配平：拖放、旋转和组合货物 | 同时满足尺寸、载荷总重和重心约束 | 有效载荷与重心配平 |
| 08 | 空域塔台：把航班排到时间轴和航道 | 协调时限、共享起降窗口及临时封闭 | 空域容量、冲突检测与错峰排程 |

每个任务包含三关，逐步增加本玩法自己的约束；难度不会只靠统一增加点位或缩短时间。八款分别采用实时驾驶、程序编排、图像拼接、证据判断、绞车操作、网络布点、货舱配平和时间排程。任务完成后按各自的操作质量与安全条件结算，并呈现“本关操作对应的原理”和配套科普档案。

01「风廊急送」使用 WASD / 方向键施加推力，Shift 刹车稳姿并消耗电量，Space 投下急救包。每关都要连续送达 3 处；进入目标圈且模拟地速低于本关上限才能投递，落点越准得分越高。教学关、侧风关和阵风关分别训练惯性预判、航迹修正与顺风减速；撞上楼体、电线杆或安全边界会立即结算。

## 架构导览

```text
src/
├── main.ts                         # 应用组装、任务切换、屏幕栈与全局快捷键
├── core/
│   ├── game-interface.ts           # 游戏模块、HUD、任务结果等共享类型
│   ├── game-registry.ts            # 八个任务模块的注册表
│   ├── canvas-minigame.ts         # 稳定的 Canvas 游戏外壳：生命周期、输入、HUD 与结算
│   ├── drone-mission-engine.ts    # 原项目运行时源码，当前八款不再依赖
│   ├── codex-data.ts               # 24 条无人机与低空运行科普条目
│   ├── save-store.ts               # 本地进度、星级和设置持久化
│   ├── audio-engine.ts             # 本地合成音效
│   └── canvas-utils.ts             # Canvas 尺寸、坐标和绘制工具
├── games/                          # 八个独立玩法：各自状态、规则、绘制、输入、计分与关卡
├── ui/                             # 任务中枢、顶栏、HUD、简报、结算和科普界面
└── styles/                         # 深色面板、青色遥测、金色任务标记等设计令牌
```

八款不共用同一套任务模拟循环。每个 `games/` 模块分别实现自己的状态、输入处理、更新、绘制、胜负条件和计分；`canvas-minigame.ts` 只提供稳定的 Canvas 外壳及生命周期、基础输入分发、HUD/按钮、科普卡和单次结算接口。这样能保持导航、深色控制台、任务简报、暂停、设置、科普档案与结算体验统一，同时让中央工作区按玩法改变。旧的 `drone-mission-engine.ts` 文件保留作原项目参考，不由八款新游戏导入。`main.ts` 管理任务实例的创建、暂停、切换和销毁；`GameHostAPI` 提供 HUD、音效、结果、存档和科普档案入口。任务进度写入独立的 `hangzhou_drone_lab_save_v1` localStorage 键，不覆盖原天宫项目存档。

## 项目所需技能

| 技能 | 用途 | 建议优先级 |
| --- | --- | --- |
| TypeScript、ES Modules、Vite | 类型安全、模块边界、开发和生产构建 | 必须 |
| Canvas 2D、动画循环与输入处理 | 绘制任务地图和无人机，处理键盘、鼠标/触控及帧更新 | 必须 |
| 可复用的前端架构与生命周期管理 | 屏幕栈、任务模块接口、HUD 事件、暂停和清理资源 | 必须 |
| 小游戏与关卡设计 | 操控反馈、目标、计分、难度曲线和三关递进 | 必须 |
| 启发式 AI 与规则建模 | 航线避障、任务分配、优先级判断、告警辅助复核 | 必须 |
| UI 视觉设计与无障碍 | 深色控制台风格、遥测层级、键盘焦点、状态颜色冗余表达 | 必须 |
| 浏览器调试与回归验证 | TypeScript 检查、生产构建、运行时冒烟与关键流程复查 | 必须 |
| 无人机与低空运行基础 | 理解续航、风扰、航测重叠、空域冲突和应急任务等教学概念 | 有帮助 |

本项目使用 **Canvas 2D**，不依赖 Three.js 或服务端。学习时可先阅读共享运行时和 `GameModule` 接口，再对照一个任务配置追踪“进入任务 → 更新 HUD/模拟 → 结算 → 存档”的完整流程。
